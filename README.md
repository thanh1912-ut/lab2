# Lab 2 - Fine-tuning Pretrained CNNs on CIFAR-10

## Objective

Compare four CNN backbones, all pretrained on **ImageNet-1K** and then **fine-tuned on
CIFAR-10** (10-class classification):

| # | Backbone | `--model` | Source | ImageNet-1K pretrained weights |
|---|----------|-----------|--------|--------------------------------|
| 1 | MobileNetV4-Small (MobileNetV4 **Conv Small**) | `mobilenetv4_small` | **timm** | `mobilenetv4_conv_small.e2400_r224_in1k` |
| 2 | VGG16 | `vgg16` | torchvision | `torchvision.models.VGG16_Weights.IMAGENET1K_V1` |
| 3 | ResNet18 | `resnet18` | torchvision | `torchvision.models.ResNet18_Weights.IMAGENET1K_V1` |
| 4 | DenseNet121 | `densenet121` | torchvision | `torchvision.models.DenseNet121_Weights.IMAGENET1K_V1` |

**No backbone is trained from scratch.** Every model loads ImageNet-1K weights and the
final classification layer is replaced by a fresh `nn.Linear(..., 10)` head.

### Why is MobileNetV4 loaded from `timm` instead of `torchvision`?

The installed torchvision version (**0.26.0**) does **not** contain any MobileNetV4
implementation — `hasattr(torchvision.models, "mobilenet_v4") == False`. MobileNetV4 was
published in 2024 (arXiv:2404.10518) and is not part of a released torchvision.

Therefore the lab uses the official **`timm`** (PyTorch Image Models, HuggingFace)
implementation, `timm.create_model("mobilenetv4_conv_small.e2400_r224_in1k", pretrained=True)`,
which is the *MobileNetV4 Conv Small* variant with ImageNet-1K weights.
**MobileNetV3 is never used as a substitute.** `smoke_test.py` prints the full list of
MobileNetV4 ImageNet-1K weight tags available in the installed timm, and if the requested
tag is missing the code raises an explicit error listing the available candidates instead
of silently falling back to another architecture.

> Implementation note (for transparency when reading the printed architecture):
> timm registers `mobilenetv4_conv_small` in `timm/models/mobilenetv3.py` and reuses the
> `MobileNetV3` **Python class** as a container, but the model is generated by
> `_gen_mobilenet_v4()` with the MobileNetV4 block definitions (FusedIB / ExtraDW / UIB
> inverted-bottleneck blocks from the MobileNetV4 paper). The printed
> `type(model).__name__` therefore says `MobileNetV3` while the architecture and the
> weights are genuinely MobileNetV4 Conv Small. This is a timm naming detail, not a
> substitution.

## Configuration

| Item | Value |
|------|-------|
| Dataset | CIFAR-10 (`torchvision.datasets.CIFAR10`, auto-download into `./data`) |
| Split | 45,000 train / 5,000 validation (from the 50,000 train images) + 10,000 official test |
| Input | 224 x 224 (all 60,000 CIFAR-10 images are upscaled from 32 x 32) |
| Train transform | `RandomResizedCrop(224, scale=(0.6, 1.0))`, `RandomHorizontalFlip(0.5)`, `ToTensor`, `Normalize` |
| Val/Test transform | `Resize(256)`, `CenterCrop(224)`, `ToTensor`, `Normalize` |
| Normalisation | ImageNet mean `[0.485, 0.456, 0.406]`, std `[0.229, 0.224, 0.225]` (identical for all 4 backbones) |
| Optimizer | **AdamW** (`torch.optim.AdamW`) |
| Learning rate | **0.005** (identical for all 4 backbones) |
| Weight decay | 1e-4 |
| LR scheduler | **none** (constant 0.005 — simple recipe; `--scheduler cosine|step` available) |
| Batch size | **32** |
| Loss | **CrossEntropyLoss** (`label_smoothing=0.0`) |
| Epochs | **20** (`--epochs` to change) |
| Pretraining | ImageNet-1K (`pretrained=True` everywhere) |
| Fine-tuning | **Full network** (all parameters trainable; `--freeze-backbone` is an optional side experiment) |
| Mixed precision | `torch.autocast` + `torch.amp.GradScaler`, enabled automatically on CUDA, disabled on CPU/MPS |
| Device | auto: **CUDA > MPS > CPU** |
| Seed | **42** (split, weights init order, augmentation, DataLoader workers) |
| Model selection | best **validation accuracy** only — the test set is never used for tuning |

Fairness rules enforced by `benchmark.py`: same split, same transforms, same seed, same
optimizer, same LR, same batch size, same epochs, same AMP setting for every backbone.

### Module responsibilities

| File | Responsibility |
|------|----------------|
| `config.py` | Dataset/transform constants, mandatory hyperparameters, `TrainConfig` dataclass, default directories. No logic, no absolute paths. |
| `models.py` | `create_model(model_name, num_classes=10, pretrained=True)`; per-architecture head replacement (ResNet `fc`, VGG `classifier[6]`, DenseNet `classifier`, timm `reset_classifier`); `freeze_backbone()` / `unfreeze_model()`; timm availability + MobileNetV4 tag validation. |
| `dataset.py` | `build_transforms()`, `load_cifar10_datasets()`, `build_dataloaders()`, `describe_dataset()`. Deterministic split via `torch.Generator().manual_seed(seed)`. |
| `engine.py` | Explicit PyTorch training loop (`model.train()`, `zero_grad`, forward, loss, `backward`, `optimizer.step()`), validation/test under `model.eval()` + `torch.inference_mode()`, AMP support, TensorBoard + CSV logging, best-checkpoint saving, `fit()`, `run_test_on_checkpoint()`. |
| `utils.py` | `set_seed()`, `get_device()`/`describe_device()`, `count_parameters()`, `save_checkpoint()`/`load_checkpoint()`, CSV/JSON helpers, `get_model_size_mb()`, version-tolerant `GradScaler`/`autocast` factories. |
| `train.py` | argparse CLI for one model: data → model → `fit()` → final test on the best checkpoint → `results/<model>_test.json`. |
| `evaluate.py` | argparse CLI: load `checkpoints/<model>_best.pt`, evaluate on the test (or val) split, update `results/<model>_test.json`. |
| `benchmark.py` | argparse CLI: loops over the 4 backbones with one identical `TrainConfig`, writes `results/model_comparison.csv`. |
| `inspect_model.py` | argparse CLI: full architecture, parameter counts, classifier, dummy-input output shape. |
| `smoke_test.py` | argparse CLI: environment/weights-API report + 4-model dummy-forward verification. |

## Training

All four commands use the mandatory recipe (ImageNet-1K pretrained, full fine-tuning,
AdamW, lr 0.005, batch size 32, 20 epochs, seed 42):


### If TensorBoard cannot be imported

`from torch.utils.tensorboard import SummaryWriter` is not a harmless import everywhere:
TensorBoard's compat layer may import TensorFlow, and a broken TensorFlow/Keras/pyarrow
installation in the environment can crash the interpreter with a native `SIGSEGV` that
Python cannot catch (this was observed with an Anaconda env whose `import tensorflow`
segfaults). Training must not die because of a logging dependency, so the import is
validated **once, out-of-process**, before it is done in-process:

```
[engine] TensorBoard logging disabled: the probe process was killed by signal 11 (native crash).
         Importing torch.utils.tensorboard pulls in TensorFlow/Keras/pyarrow, ...
         Training continues without TensorBoard; ...
```

Training, checkpointing, the CSV history and the test JSON all continue normally; only the
`runs/<model>/` event files are skipped. Control this with the environment variable
`LAB2_TENSORBOARD`:

| Value | Behaviour |
|-------|-----------|
| `auto` (default) | Probe in a subprocess; disable logging gracefully if the probe crashes |
| `1` / `true` | Import in-process without probing (fast path on known-good machines) |
| `0` / `false` | Disable TensorBoard entirely (same as `--no-tensorboard`) |

```bash
LAB2_TENSORBOARD=1 python train.py --model resnet18 --epochs 20   # force TensorBoard on
python train.py --model resnet18 --epochs 20 --no-tensorboard     # skip it entirely
```

## Evaluation

```bash
# evaluate checkpoints/resnet18_best.pt on the 10,000-image official test split
python evaluate.py --model resnet18

# explicit checkpoint file
python evaluate.py --checkpoint checkpoints/vgg16_best.pt

# validate on the 5,000-image validation split instead
python evaluate.py --model resnet18 --split val
```

`train.py` already performs the final test evaluation on the best checkpoint and writes
`results/<model>_test.json`, so `evaluate.py` is mainly for re-checking or re-running an
existing checkpoint. Checkpoints always contain the validation accuracy, so the reported
`best_val_accuracy` is the value that selected the checkpoint.

## Benchmark

Sequentially trains and compares all four backbones with an identical configuration:

```bash
python benchmark.py --epochs 20 --batch-size 32 --lr 0.005
```

Subset / quick smoke run:

```bash
python benchmark.py --models resnet18 vgg16 --epochs 2
python benchmark.py --models resnet18 --epochs 1 --limit-train-batches 5 --limit-eval-batches 2
```

It produces `results/model_comparison.csv`:

| model | total_params | trainable_params | best_epoch | best_val_accuracy | test_accuracy | training_time_minutes | model_size_mb |
|-------|--------------|------------------|------------|-------------------|---------------|-----------------------|---------------|

(`model_size_mb` is the size of the saved best checkpoint; it is the optional extra
column from the lab description. FPS is intentionally not measured.)

Per-model `results/<model>_history.csv` and `results/<model>_test.json` are written as well.

The final table is printed as plain text by default. `--pandas-table` prints it with
pandas instead; that import is opt-in because pandas' native dependency chain can be
broken in the same way TensorBoard's can (see above). The CSV itself is always written
with the standard library `csv` module and is never affected.

## Reproducibility

`utils.set_seed(42)` seeds `random`, `numpy`, `torch`, `torch.cuda` (and `PYTHONHASHSEED`),
and DataLoader workers get deterministic seeds through `worker_init_fn`. The
train/validation split is produced by `torch.Generator().manual_seed(seed)`, so it is
identical for all four backbones and independent of any previous RNG consumption —
a precondition for a meaningful backbone comparison. Full bitwise determinism on GPU is
not guaranteed (cuDNN autotuning is enabled for speed; `set_seed(..., deterministic=True)`
in `utils.py` turns it off if you need strict determinism at the cost of speed).

## Assumptions and notes

1. **MobileNetV4 must come from timm** in this environment: torchvision 0.26 has no
   MobileNetV4. Variant used: *MobileNetV4 Conv Small*, weights
   `mobilenetv4_conv_small.e2400_r224_in1k` (ImageNet-1K, 224x224). Alternatives available
   in timm 1.0.28: `mobilenetv4_conv_small.e1200_r224_in1k`,
   `mobilenetv4_conv_small.e3600_r256_in1k` (256x256 pretraining). Change
   `weights_id` in `models.MODEL_SPECS` if you prefer another tag.
2. The ImageNet-1K preprocessing of the four backbones is aligned to a single pipeline
   (224x224, ImageNet mean/std). timm's MobileNetV4 default crop ratio `0.875` equals
   `CenterCrop(224)/Resize(256)`, so the shared pipeline matches it.
3. `--val-split 5000` is a fixed hold-out from the CIFAR-10 train split; the official test
   split is touched exactly once per model, after training, using the best-validation
   checkpoint.
4. `pretrained=False` appears in exactly one legitimate place: `evaluate.py` /
   `engine.load_finetuned_model()` rebuild the architecture without downloading ImageNet
   weights because every parameter is immediately overwritten by the fine-tuned
   checkpoint. Training always uses `pretrained=True`.
5. `--freeze-backbone` is provided for optional experiments only; the main benchmark is
   full fine-tuning, as required.
6. VGG16 has ~138M parameters (of which ~119M are in the two 4096-wide classifier layers).
   It is by far the slowest/largest model in the comparison; that is expected and is part
   of the discussion, not a bug.
7. `--limit-train-batches` / `--limit-eval-batches` are debug helpers for smoke tests; they
   must not be used for the reported benchmark numbers. Note that a debug run restricted to
   only a handful of batches (say < 30 steps/epoch) can report a very large validation loss
   while the training loss looks normal: with full fine-tuning at lr=0.005 the randomly
   initialized head and the BatchNorm running statistics need a few hundred steps to settle.
   It is an artifact of the truncated run, not of the pipeline - a normal 45,000-image epoch
   is 1,407 steps and behaves normally.
8. Environment note: if `import tensorflow` in your Python environment crashes (broken
   TensorFlow/Keras/pyarrow), TensorBoard logging is disabled automatically with an explicit
   message instead of taking the training process down - see the TensorBoard section. The
   `runs/` folder is still created, and everything else is unaffected.
